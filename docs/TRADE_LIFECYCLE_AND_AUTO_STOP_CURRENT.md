# Trade lifecycle and auto-stop — current mechanisms (as-built)

**Audience:** GPT / agent project manager preparing an Active Trade Supervisor and auto-stop overhaul (especially fewer concurrent 15m markets).  
**Status:** Descriptive only. Not a redesign plan.  
**Authority:** Prefer **code** over older narrative docs. When schema text conflicts with `.cursor/rules/00-no-fallbacks.mdc` or `backend/core/kalshi_lifecycle_trade_outcome.py`, **code wins**.  
**Snapshot date:** 2026-09-07 (repo working tree).

---

## 0. One-paragraph summary

Trades are opened by **AES** (auto) or **main_app / UI** (manual) or **ATS flip-sell** after certain auto-stops; all opens go through **trade_manager** (`POST /trades` or Redis `trading:tm:commands`). Live orders are placed by **trade_executor**; fills return via **kalshi_account_sync** → TM **confirm_open**. Open positions are enrolled into **one unified ATS per tenant**, which marks high/low, evaluates strategy-specific **auto-stop** rules (gated by the same `monitor_list.auto_trade` flag as entry), and may flip-sell. Closes go back through TM → executor (buy opposite leg). Holds expire via TM’s **15-minute APScheduler** (`status=expired`), then **Kalshi lifecycle** (or 5-min `/events` backfill) writes `market_result`, then TM **finalize_expired** → `closed` and `win_loss_confirmed` from venue only. Cascading failure detector is **process health**, not trade exits.

## 2. Canonical data model

| Store | Purpose |

| `users_<NNNN>.orders_<NNNN>` (+ fills/positions) | Broker mirror for open/close confirm |
| Archive | `archive.trades_archive_{live\|paper}_*` |

### 2.2 Active-trade operational pool (ATS hot path)

| Store | Key / table | Notes |
|-------|-------------|-------|
| Redis hash | `live_state:tenant:{slot}:active_trades` | Default hot path when live_state on (`LIVE_STATE_ACTIVE_TRADES_ENABLED`, default 1) |
| PG pool | `active_trades_15m_<NNNN>`, `active_trades_hourly_<NNNN>` | Unified ATS; optional dual-write (`LIVE_STATE_ACTIVE_TRADES_PG_DUAL_WRITE`) |
| Legacy PG | `active_trades_<user>_<monitorId>` | Older layout; still referenced in audits |

**ATS pool statuses (operational, not `trades_*` status):** `pending` | `active` | `closing`.  
Only **`active`** rows are mark-updated and auto-stop evaluated.

**Module:** `backend/core/live_state_active_trades.py`.

### 2.3 Important `trades_*` statuses (TM)

Typical progression:

```
pending → open → closing → closed
                ↘ expired → closed   (after market_result finalize)
```

Also seen: `partial` (fill-related), `ERROR` (swept/deleted by expiry job).  
**Retired:** durable `close_failed` status — failed closes leave row **`open`**; ATS may retry with trigger `close_attempt_failed` / close_method `auto_close_retry`.

### 2.5 `entry_method` values

| Value | Source |
|-------|--------|
| `auto_entry` / notify `auto` | AES |
| `manual` | UI / `trigger_open_trade` |
| `flip_sell` | ATS after qualifying auto-stop |
| `simulated_15m` | AES sim path |

### 2.6 Settlement / confirmation fields

| Field | Meaning (code truth) |
|-------|----------------------|
| `market_result` | Venue `yes`/`no` from Kalshi lifecycle (or `/events` backfill). NULL until known. |
| `win_loss` | Recorded W/L on close or finalize |
| `win_loss_confirmed` | Compare recorded `win_loss` to expected from **`market_result` + `side`**. NULL until both computable. **Never** from `symbol_expiration` / spot guesses. |
| `symbol_close` / `symbol_expiration` | Spot snapshots for analytics; **not** venue outcome |
| `monitor_confirmed` | `(high_price != low_price)` after ATS tracking — “marks moved,” not venue confirm |

**Stale schema wording:** `docs/MASTER_DB_SCHEMA_REFERENCE.md` still describes `win_loss_confirmed` via strike vs `symbol_expiration`. Ignore that; use `compute_win_loss_confirmed_from_venue` in `kalshi_lifecycle_trade_outcome.py` and NO-FALLBACKS rule.

## 3. Opening trades

### 3.1 Entry paths

```
AES (auto_trade ON + strategy gates)
  └─► trigger_auto_entry_trade → Redis TM commands or HTTP POST /trades

UI / main_app
  └─► POST /api/trigger_open_trade → trade_actions → TM POST /trades

ATS flip-sell (after auto-stop)
  └─► trigger_flip_sell_open_after_auto_stop → TM open (inverted side)
```

**Key files:**

- `backend/auto_entry_supervisor.py` — `is_auto_trade_enabled`, `trigger_auto_entry_trade`
- `backend/web/routers/auto_entry_main_routes.py`, `backend/web/trade_actions.py`
- `frontend/js/strike-table.js`, `frontend/js/trade-monitor-new-init.js`, `frontend/js/trade-execution-controller.js`
- `backend/trade_manager.py` — `add_trade` (`POST /trades`)

### 3.2 AES gates (high level)

- Master gate: `monitor_list.auto_trade` (same boolean ATS uses for auto-stop).
- UI status field: `auto_trade_status` (inactive/active/etc.) — display / orchestration, distinct from script lifecycle `status`.
- Strategy-specific entry logic (Hourly HTC, Expiration Scalp, Momentum Scalp/Reversal/Breakout/Contain, Reverse HTC, High Water family, …).
- Common gates: differential, strike-vs-spot, cooldown, already-traded, loss-prevention sizing, spike alerts, strike pipeline health.

Settings: `backend/core/auto_entry_settings_store.py`; MM Redis stream `trading:mm:monitor_settings`.

### 3.3 TM open pipeline (`add_trade`)

1. Enrich from monitor: TIF, min_fill, min_slippage, limit/stop offsets (`_enrich_open_trade_execution_from_monitor`).
2. Dupe-monitor pairing if configured.
3. Prechecks: `_min_fill_price_precheck_message`, `_min_slippage_precheck_message` (order-book projection).
4. Insert row `status=pending`.
5. **Paper:** promote to `open` without executor; background ATS pending+open notify.
6. **Live:** notify executor (Redis `trading:executor:trigger` or HTTP); store `order_id_open` when accepted.
7. On fill: `confirm_open_trade` / `confirm_open_trade_for_order_id` → `status=open` → ATS enroll with ACK.

### 3.4 Executor and fill confirmation

- `backend/trade_executor.py` — `process_trigger_trade_request`; WS pipeline health gate.
- Close intent = **buy opposite leg** (do not invert side in the close payload; ATS documents this explicitly).
- `kalshi_account_sync_ws` writes orders/fills → `rec_io:tm:positions_updated` or HTTP `/api/positions_updated` → TM confirm.

### 3.5 ATS enrollment transport

- Open enroll: Redis `rec_io:ats_enroll_request` + ACK keys `ats:enroll:result:{correlation_id}` (`backend/core/ats_enrollment_redis.py`).
- Non-open statuses: `rec_io:ats_tm_notifications`.
- Helpers: `notify_ats_trade_open_with_ack`, `notify_active_trade_supervisor_direct*`.
- ATS handlers: `add_pending_trade`, `confirm_pending_trade`, `add_new_active_trade`.

**Failure mode (historical):** if confirm_open never completes or “open” never reaches ATS, row stays `pending` in pool → no marks → `monitor_confirmed=FALSE` at close. See audit doc.

## 4. Tracking active trades (ATS)

### 4.1 Responsibilities

| Concern | Mechanism |
|---------|-----------|
| Enroll / de-enroll | pending → active → closing → remove |
| Marks | high/low, current close (opp ask), symbol price, live probability |
| Auto-stop | strategy router `check_auto_stop_conditions*` |
| Flip-sell | after successful floor/prob auto-stop enqueue |
| Stale cleanup | `flush_stale_active_trades_past_contract_settlement` |
| Resilience | `check_monitoring_failsafe`, `check_ats_self_heal` |
| UI wakeups | trade marks WS, `broadcast_active_trades_change`, live_state channel |

**Primary file:** `backend/active_trade_supervisor.py` (~8.7k lines).

### 4.2 Monitoring loop (conceptual)

1. Ensure monitoring loop started when first pending/active trade appears (`start_monitoring_loop`).
2. Load pool rows with `status=active` (Redis and/or PG).
3. For each trade: resolve closing price from Kalshi snapshot / strike tables; update high/low.
4. If `is_auto_stop_enabled()` and not reverse monitor: run strategy auto-stop checks.
5. Failsafe / self-heal / stale flush on timers.

**Mark source risk:** if ticker missing after event rotation / truncate, closing price can be None → skip update → high/low stall → `monitor_confirmed` false. See `docs/DIAGNOSIS_MONITOR_CONFIRMED_FALSE.md`.

### 4.3 What monitor_manager does / does not do

`monitor_manager` handles bankroll allotments, settings persistence, trade-closed stats / loss-prevention hooks, supervisor sync. It does **not** compute per-tick PnL or fire auto-stops.

### 4.4 Traeflow wakeups

`backend/core/tradeflow_live_state_trigger.py` — wake AES/ATS on live_state updates (env-gated).

## 5. Auto-stop mechanics (ATS) — detail for overhaul

### 5.1 Master gates

| Gate | Behavior |
|------|----------|
| `monitor_list.auto_trade` | **Same flag as AES entry.** `is_auto_stop_enabled()` reads this. There is **no separate auto-stop toggle**. |
| `monitor_list.reverse` | Auto-stop **skipped** entirely (`is_reverse_monitor`). |
| Strike pipeline gate | `evaluate_pipeline_gate_conn` can block `trigger_auto_stop_close` (and opens). |
| Stale-fire guards | `_ats_refuse_stale_fire` before pipeline / submit. |
| Past settlement | `should_suppress_auto_close_past_kalshi_settlement` skips close. |
| Missing prices | Skip close if `current_close_price` or `current_symbol_price` missing. |

### 5.2 Strategy router

`check_auto_stop_conditions` →

| Strategy | Handler | Primary exits |
|----------|---------|---------------|
| Momentum Scalp | `…_momentum_scalp` | floor; max_profit; trailing; profit target; momentum spike |
| Momentum Reversal | `…_momentum_reversal` | floor; reversal_* variants |
| Reverse HTC | `…_hourly_htc` | same as HTC |
| High Water family | `…_high_water_scalp` | floor (+ optional stop verify); paper GTC book sim; resting `limit_close` |
| Expiration Scalp | `…_expiration_scalp` | **floor only** (no prob / min_ttc / momentum / verification) |
| Hourly HTC / default | `…_hourly_htc` | floor then probability stop |

There is **no** column named `take_profit`. Profit exits are `max_profit`, momentum profit targets / trailing, or HWS `limit_close_*`.

### 5.3 Probability auto-stop (HTC / default)

- Threshold: `get_auto_stop_threshold()` ← monitor **`current_probability`** (misnamed: this is the **stop threshold**, not live market prob).
- Live mark on trade dict: also called `current_probability` in the active pool (live estimated prob).
- Fire when live prob **&lt; threshold**, status `active`, TTC ≥ `min_ttc`, not already triggered.
- Optional **verification dwell:** `stop_verification_period_*` — condition must still hold after N seconds.
- Maps to `trigger_reason=probability_auto_stop` → `close_method=auto_probability`.

### 5.4 Stop-loss ask floor (shared)

`_try_stop_loss_ask_floor`:

- Monitor `stop_loss_price`: **0 disables**. When opposite-side ask &gt; `(1 − stop_loss_price)`, floor is hit.
- Optional guards (env, default on):
  - `ATS_STOP_LOSS_FLOOR_GUARD`
  - `ATS_STOP_LOSS_FLOOR_MAX_QUOTE_DISAGREE` (default 0.18)
  - `ATS_STOP_LOSS_FLOOR_CONFIRM_TICKS` (default 2)
  - `ATS_STOP_LOSS_FLOOR_PROB_MARK_DIVERGENCE_POINTS` (default 50; 0 disables)
- HTC path still respects `min_ttc` unless strategy disables (Expiration Scalp passes `0,0` and `check_probability_divergence=False`).
- Maps to `trigger_reason=stop_loss_floor` → `close_method=auto_stop_loss_floor`.

### 5.5 Momentum Scalp / Reversal (summary)

Uses owned-side / close marks vs `high_price`, `buy_price`, plus:

- `momentum_scalp_trailing_stop_amount`
- `momentum_scalp_profit_target`
- `max_profit`
- `momentum_scalp_entry_threshold` + live momentum percentile (spike exit)
- Shared floor via `_try_stop_loss_ask_floor`

### 5.6 High Water Scalp family

- Resting GTC close at `limit_close_price` / offset strategies (`limit_close_offset`, `stop_loss_offset` on trade snapshot).
- Partial fills: `close_filled_count`; remaining = position − filled.
- Auto-stop flatten: cancel resting GTC then market-close remainder (`_hws_cancel_resting_and_apply_remaining`).
- Paper: no Kalshi GTC — ATS simulates book fills (`high_water_scalp_paper`) and enqueues `intent=paper_hws_resting_fill`.
- Helpers: `backend/core/high_water_scalp.py`, `backend/core/high_water_scalp_paper.py`.

### 5.7 Close payload shape (`trigger_auto_stop_close`)

Same conceptual shape as manual close:

- `intent` / `action`: close
- `side`: **position side** (not inverted)
- `order_type`: market, `time_in_force`: immediate_or_cancel
- `buy_price`: computed sell (1 − opposite ask)
- `close_method`: mapped from trigger
- Transport: Redis `publish_trade_manager_command("add_trade", …)` preferred; HTTP fallback gated by `ATS_HTTP_FALLBACK_ENABLED`

On successful enqueue (unified pool): defer trade_logger + preferences notify; optionally enqueue flip-sell.

### 5.8 Flip-sell

`trigger_flip_sell_open_after_auto_stop`:

- Only after **successful** auto-stop close enqueue.
- Only for `stop_loss_floor` or `probability_auto_stop`.
- Monitor `flip_sell_floor` / `flip_sell_prob` must be **PostgreSQL TRUE** (strict; NULL/false never enables).
- Size: closed position × `flip_sell_*_mult` (parsed e.g. `1x`).
- Opens **inverted** side; `entry_method=flip_sell`.
- **No chain:** if closed trade’s entry was already `flip_sell`, skip.
- Subject to pipeline gate and loss-prevention sizing awareness.

### 5.9 Loss prevention (not an exit engine)

| Module | Role |
|--------|------|
| `backend/core/time_based_loss_prevention.py` | Time / streak LP on monitors after closes |
| `backend/core/symbol_wide_loss_prevention.py` | Hero → `live_data.live_symbol_status` → followers |
| System settings | `market_wide_loss_prevention`, `stop_loss_count_threshold` |

These **throttle or block new size**; they do not replace ATS closes.

### 5.10 Cascading failure detector (naming trap)

`backend/cascading_failure_detector.py` watches critical supervisord programs and may drive **master restart**. It does **not** cascade-close trades or set stops.

## 6. Closing trades (non-expiry)

### 6.1 Paths

| Path | Entry |
|------|-------|
| Manual | UI `closeTrade` → TM close (same `/trades` close shape) |
| Auto-stop | ATS → TM |
| HWS limit_close | Resting GTC + partial fill accounting |
| Broker confirm | `confirm_close_trade` / `confirm_close_trade_for_order_id` |
| Close fail | `_mark_close_trade_failed` — leave **`open`**; ATS may retry |

### 6.2 TM close progression

`open` → `closing` → `closed`

`update_trade_status_with_ret_pct` writes PnL, fees, ROI, high/low from active pool, `monitor_confirmed`, `close_method`. Notifies ATS (`closing` / `closed`), MM trade-closed, preferences / strike WS.

## 7. Expiry and settlement

### 7.1 TM APScheduler jobs

| Job | Cadence (ET) | Function |
|-----|--------------|----------|
| Expiry sweep | every 15 min at `:00/:15/:30/:45` | `check_expired_trades` |
| Outcome backfill | every 5 min | `check_expired_trades_for_settlements` → `backfill_missing_market_results_from_kalshi` |
| Cycle performance | 03:15 | `refresh_all_monitor_cycle_performance` |

### 7.2 `check_expired_trades` behavior

1. Delete ERROR trades; delete unfilled pending past expiry.
2. Backfill `symbol_expiration` for early-closed rows past contract end.
3. Select `open`/`closing`/`partial`; at non-`:00` minutes only **15m** market rows; at `:00` all.
4. Filter with `_filter_trades_past_contract_expiration`.
5. Set `status=expired`, `close_method=expired`, snapshot `symbol_close` / `symbol_expiration` when available.
6. Notify ATS `"expired"`.
7. If `market_result` already present (esp. paper), may finalize immediately.

Sim: `check_expired_simulated_trades` on `trades_simulated_*`.

### 7.3 Venue `market_result` path

```
market_watchdog_ws (lifecycle_v2 determined/settled)
  → Redis (kalshi lifecycle trades channel/stream)
  → kalshi_lifecycle_consumer_<NNNN>
  → apply_lifecycle_market_result_for_ticker
       → SET market_result
       → SET win_loss_confirmed when win_loss already present
       → finalize_expired_trade_from_market_result for expired rows
```

**Files:**

- `backend/core/kalshi_lifecycle_trade_outcome.py`
- `backend/kalshi_lifecycle_trade_consumer.py`
- `backend/core/kalshi_lifecycle_pending_tickers.py` (read-only cross-tenant for WS subscription planning)

**Safety net:** TM Kalshi `/events` backfill every 5 minutes; per-ticker schedule `_schedule_market_result_backfill_for_ticker`. Also backfills strike archive.

**Deadlocks:** lifecycle consumer vs TM/ATS on same `trades_*` rows — retries + stable `ORDER BY id FOR UPDATE`.

### 7.4 Finalize expired → closed

`finalize_expired_trade_from_market_result`:

- Requires `status==expired` **and** non-null `market_result`.
- `win_loss` from `expiry_win_loss_from_market_result(side, market_result)`.
- Remainder settles at 1.00 / 0.00; live HWS may blend GTC VWAP slice + remainder.
- Idempotent.

### 7.5 NO FALLBACKS (settlement)

Do not invent `market_result` or `win_loss_confirmed` from spot / `symbol_expiration` / strike math. Missing venue data stays NULL until WS or API backfill.

## 10. Monitor / strategy knobs that matter for auto-stop overhaul

### 10.1 Shared / HTC

| Field | Role |
|-------|------|
| `auto_trade` | Enables AES **and** ATS auto-stop |
| `auto_trade_status` | UI / orchestration status string |
| `reverse` | Disables auto-stop |
| `current_probability` | **Auto-stop probability threshold** (not live prob) |
| `stop_loss_price` | Ask-floor stop; 0 = off |
| `stop_verification_period_enabled` / `_seconds` | Prob (and HWS floor) dwell |
| `min_ttc` | Block prob/floor stops too near expiry (strategy-dependent) |
| `min_probability` / `max_probability` | Entry band (AES), not ATS stop |
| `flip_sell_prob` / `flip_sell_floor` | Strict TRUE gates |
| `flip_sell_*_mult` | Flip size multiplier tokens |
| `min_fill_price` / `min_slippage` / `time_in_force` / `order_type` | Open enrichment |
| Loss-prevention family | Size/throttle only |

### 10.2 Momentum

`momentum_scalp_entry_threshold`, `momentum_scalp_trailing_stop_amount`, `momentum_scalp_profit_target`, `max_profit`.

### 10.3 High Water

`limit_close_price`, `limit_close_offset`, `stop_loss_offset` (snapshotted onto trade at open/confirm).

### 10.4 Env knobs (ATS / live_state)

| Env | Effect |
|-----|--------|
| `USE_TRADING_REDIS_COMMS` | Streams vs HTTP |
| `LIVE_STATE_ACTIVE_TRADES_*` | Redis active pool / PG dual-write |

## 14. Known quirks / landmines for the overhaul PM

1. **`auto_trade` is one switch for entry and auto-stop** — splitting them is a product/schema change, not a flag that already exists.
2. **`current_probability` on monitor = stop threshold**; live prob lives on the active-trade mark dict under the same name — easy to confuse in code review.
3. **Unified ATS** replaced per-monitor OS processes; audits and some comments still describe old ports/tables.
4. **Failed closes stay `open`** — retries are ATS-side (`close_attempt_failed`), not a terminal `close_failed` status.
5. **Schema reference still wrong on `win_loss_confirmed`** — venue-only in code.
6. **Cascading failure ≠ cascading stops.**
7. **Flip-sell is strict TRUE + no chain** on `flip_sell` entries.
8. **Pipeline health can silently block auto-stops** (logged as BLOCKED).
9. **Expiration Scalp auto-stop is floor-only** — no probability stop path.
10. **HWS mixed expiry closes** can produce net-PnL-based W/L vs pure binary settlement.
11. **Fewer concurrent 15m markets** affects AES selection and ATS pool size, but auto-stop logic is still **per-monitor strategy** inside one unified process — overhaul should decide whether marks/stops stay per-trade in one loop or need market-scoped prioritization.
12. **Paper vs live:** paper skips TE for open/close but still needs lifecycle/`market_result` for expired finalize; HWS paper GTC is ATS-simulated.
